# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Проект

`supervisor-rs` — минимальный супервизор процессов (мини-systemd) для Unix, на
Rust. Демон стартует/следит/рестартует процессы по policy и корректно гасит всё
дерево потомков через process-группы. Учебный соло-pet-проект, бюджет $0, **первый
Rust в портфеле** — тема выбрана как практика системного программирования.

Ориентиры: `docs/PLAN.md` (видение/этапы), `docs/TECHNICAL_PLAN.md` (стек,
разбивка по Этапам), `docs/POST_MVP_PLAN.md` (за рамками MVP),
`.claude/skills/rust-process-supervisor-dev/SKILL.md` (конвенции кода).

## Конвенции

- **Язык.** Документация и subject коммитов — на русском; код, идентификаторы и
  комментарии в коде — на английском.
- **Терминология этапов** — «Этап N», сквозная в docs, коде (`TODO(Этап N)`) и
  ветках.
- **Коммиты.** Conventional-commit с русским subject, например
  `feat(этап-2): restart policy + exponential backoff`. Завершать коммит трейлером
  `Co-Authored-By: Claude <noreply@anthropic.com>`.
- **Docker Compose не используется** — CLI-демон без внешних зависимостей.
  Не добавлять.

## Команды

```bash
cargo check          # быстрая проверка компиляции
cargo build          # сборка
cargo run            # запуск
cargo test           # все тесты (юнит + интеграционные)
cargo fmt --check    # проверка форматирования
cargo clippy -- -D warnings   # линт без варнингов
```

Перед коммитом прогнать: `cargo fmt --check`, `cargo clippy -- -D warnings`,
`cargo test`.

## Git-workflow

- На каждый Этап — новая ветка от `master` (например `этап-2/restart-policy`).
- Работа в ветке → PR → merge в `master`.
- Не коммитить и не пушить без явного запроса пользователя.

## Тестирование сигналов и деревьев процессов

Ключевая сложность проекта — детерминированная проверка POSIX-механики. См.
детали в `.claude/skills/rust-process-supervisor-dev/SKILL.md`. Кратко: сигналы и
process trees тестируются через реальные дочерние процессы-заглушки (short-lived
хелперы, форкающие потомков), с маркер-файлами и `kill(pid, 0)` для проверки
жив/мёртв — а не только на «простом child».
