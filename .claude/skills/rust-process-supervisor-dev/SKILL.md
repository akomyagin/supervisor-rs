# SKILL: rust-process-supervisor-dev — конвенции проекта `supervisor-rs`

Скилл для реализации кода супервизора процессов. Проект — первый Rust в портфеле;
цель — аккуратная POSIX-механика (сигналы, process groups, реапинг зомби).

## Стек и слои

- `src/config.rs` — чистый парсинг TOML через `serde` + `toml`, без сайд-эффектов
  (легко юнит-тестировать).
- `src/process.rs` — вся системная механика: spawn, monitor, restart, teardown.
- `src/main.rs` — инициализация `tracing`, разбор CLI, запуск supervise loop.
- Логи — только через `tracing` (не `println!`), уровень через `RUST_LOG`.

## Работа с крейтом `nix`

`nix` (features `signal`, `process`) — безопасные обёртки над libc. Не тянуть
сырой `libc`, если `nix` покрывает нужное.

- **Сигналы:** `nix::sys::signal::{kill, killpg, Signal}` для доставки;
  `sigaction`/`SigAction` — для установки обработчиков (Этап 3).
- **Process groups (Этап 4):** `nix::unistd::{setsid, setpgid, Pid}`. Каждый
  супервизируемый процесс — лидер своей группы, чтобы `killpg` бил всё дерево, а
  не только прямого ребёнка.
- **Реапинг:** `nix::sys::wait::{waitpid, WaitPidFlag, WaitStatus}`; неблокирующий
  реапинг — с `WaitPidFlag::WNOHANG` в monitor-loop, чтобы не копить зомби.
- **Spawn с pre_exec:** ставить процесс-группу в хуке между fork и exec —
  `std::os::unix::process::CommandExt::pre_exec`:

  ```rust
  use std::os::unix::process::CommandExt;
  // SAFETY: pre_exec runs in the forked child before exec; only
  // async-signal-safe calls are allowed. setsid() qualifies.
  unsafe {
      cmd.pre_exec(|| {
          nix::unistd::setsid().map(|_| ()).map_err(std::io::Error::from)
      });
  }
  ```

  Помнить про правила async-signal-safety внутри `pre_exec`: никаких аллокаций,
  логов, мьютексов — только простые syscalls.

## Обработчики сигналов: self-pipe / signalfd

Обработчик сигнала почти ничего не может делать безопасно: хендлер лишь
регистрирует факт сигнала, а решения (форвард детям, инициировать shutdown)
принимает основной loop. Не звать async-signal-unsafe код прямо в хендлере.

**Какой механизм выбирать — зависит от того, на чём висит цикл.** Self-pipe и
`signalfd` существуют, чтобы *разбудить* цикл, блокирующийся на дескрипторе
(`select`/`poll`/`read`). Если цикл — поллинг с периодическим sleep, будить
нечего: достаточно атомарного флага (`AtomicI32` + `store` в хендлере,
опрос на каждой итерации), и это проще — нет fd, нет `O_NONBLOCK`, нет
EINTR-ретраев, нет `FD_CLOEXEC` от утечки дескрипторов в детей. Цена — латентность
до одного тика. Так и сделано в Этапе 3 (`src/signal.rs`); если цикл станет
событийным (unix-socket с `poll` в Этапе 5) — переходить на self-pipe/signalfd.

Диспозиция `SIG_IGN` наследуется через `exec`, а установленный хендлер при `exec`
сбрасывается в `SIG_DFL`. Поэтому супервизору **нельзя** глушить SIGTERM через
`SigIgn`: дети унаследуют глухоту.

## Teardown дерева (ядро проекта, Этап 4)

`terminate_tree(pgid, grace)`:
1. `killpg(pgid, SIGTERM)`.
2. Ждать до `grace`, в это время реапить `waitpid(WNOHANG)`.
3. Если группа ещё жива — `killpg(pgid, SIGKILL)`, затем дореапить.

Форвардинг из Этапа 3 после Этапа 4 переходит с `kill(pid)` на `killpg(pgid)`.

## Тестирование сигналов и деревьев (детерминированно)

Главная ловушка — протестировать только «простой child». Обязательно покрывать
случай «child, который сам форкнул детей».

Паттерн: **дочерние процессы-заглушки** (helper-скрипты или отдельные тестовые
бинарники), которые ведут себя предсказуемо, плюс файлы-маркеры и проверки
`kill(pid, 0)`:

- **Заглушка-падалка:** выходит с заданным кодом/по сигналу — для проверки
  restart policy (Этап 2). Код выхода/задержку задавать через argv или env.
- **Заглушка-ловец SIGTERM:** ставит хендлер, пишет маркер-файл «got SIGTERM»
  перед выходом — проверка форвардинга (Этап 3).
- **Заглушка-родитель с детьми:** форкает 2–3 долгоживущих ребёнка в своей
  группе, печатает их PID-ы в stdout/файл — проверка teardown дерева (Этап 4).
  После `terminate_tree` тест читает PID-ы и убеждается, что все мертвы
  (`kill(pid, 0)` → `Err(ESRCH)`), и что зомби не осталось.
- **Заглушка-игнорщик SIGTERM:** глушит SIGTERM — проверка пути SIGKILL по
  таймауту (Этап 4).

Технические приёмы для детерминизма:
- Проверка «жив ли pid»: `nix::sys::signal::kill(pid, None)` (сигнал 0) →
  `Ok` = жив, `Err(Errno::ESRCH)` = мёртв.
- `tempfile` (dev-dep) — для скретч-директорий и маркер-файлов, чтобы не сорить
  в репо.
- Backoff/таймауты тестировать с инъекцией «часов» (трейт-абстракция над
  временем), чтобы не спать реальные секунды и не делать тесты флаки.
- Хелперы-заглушки держать в `tests/` (отдельные бинарники через
  `[[bin]]`/`tests/bin/`) или как shell-скрипты рядом с интеграционными тестами.

## Пирамида тестов

- **Юнит:** парсинг конфига (валидный/битый), логика policy (решение
  рестартить/нет по коду выхода), расчёт backoff — без реальных процессов.
- **Интеграционные:** реальный spawn заглушек, сигналы, teardown дерева — на
  реальном стеке процессов (детерминированные фейки, а не мок-HTTP).
