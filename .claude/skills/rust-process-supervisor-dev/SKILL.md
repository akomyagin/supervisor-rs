# SKILL: rust-process-supervisor-dev — конвенции проекта `supervisor-rs`

Скилл для реализации кода супервизора процессов. Проект — первый Rust в портфеле;
цель — аккуратная POSIX-механика (сигналы, process groups, реапинг зомби).

## Стек и слои

- `src/config.rs` — чистый парсинг TOML через `serde` + `toml`, без сайд-эффектов
  (легко юнит-тестировать).
- `src/process.rs` — вся системная механика: spawn, monitor, restart, teardown.
- `src/cli.rs` (Этап 5) — ручной разбор `argv` в `Command`; чистая функция, живёт
  в библиотеке, чтобы быть юнит-тестируемой.
- `src/state.rs` (Этап 5) — схема снапшота состояния плюс атомарные
  запись/чтение файла, который читает подкоманда `status`.
- `src/main.rs` — инициализация `tracing`, диспетчер подкоманд, exit-коды.
- Логи — только через `tracing` (не `println!`), уровень через `RUST_LOG`.
  Исключение — **результат** CLI-команды (таблица `status`, текст помощи,
  usage-ошибка): это ответ пользователю, а не лог демона, и печатается через
  `println!`/`eprintln!`.

## Работа с крейтом `nix`

`nix` (features `signal`, `process`) — безопасные обёртки над libc. Не тянуть
сырой `libc`, если `nix` покрывает нужное.

- **Сигналы:** `nix::sys::signal::{kill, killpg, Signal}` для доставки;
  `sigaction`/`SigAction` — для установки обработчиков (Этап 3).
- **Process groups (Этап 4):** `nix::unistd::{setsid, Pid}` (`setpgid`
  рассмотрен и отвергнут — см. раздел про teardown). Каждый
  супервизируемый процесс — лидер своей группы, чтобы `killpg` бил всё дерево, а
  не только прямого ребёнка.
- **Реапинг:** гибрид — неразрушающий peek `nix::sys::wait::waitid` с
  `WEXITED | WNOHANG | WNOWAIT` для обнаружения выхода, а сам реапинг остаётся за
  `std::process::Child::try_wait()`, чтобы не было двойного реапинга. Подробности
  и порядок вызовов — в разделе «Teardown дерева».
- **Spawn с pre_exec:** ставить процесс-группу в хуке между fork и exec —
  `std::os::unix::process::CommandExt::pre_exec`:

  ```rust
  use std::os::unix::process::CommandExt;
  // SAFETY: pre_exec runs in the forked child before exec; only
  // async-signal-safe calls are allowed. setsid() qualifies.
  unsafe {
      cmd.pre_exec(|| {
          nix::unistd::setsid().map(|_| ()).map_err(std::io::Error::from)
      });
  }
  ```

  Помнить про правила async-signal-safety внутри `pre_exec`: никаких аллокаций,
  логов, мьютексов — только простые syscalls.

## Обработчики сигналов: self-pipe / signalfd

Обработчик сигнала почти ничего не может делать безопасно: хендлер лишь
регистрирует факт сигнала, а решения (форвард детям, инициировать shutdown)
принимает основной loop. Не звать async-signal-unsafe код прямо в хендлере.

**Какой механизм выбирать — зависит от того, на чём висит цикл.** Self-pipe и
`signalfd` существуют, чтобы *разбудить* цикл, блокирующийся на дескрипторе
(`select`/`poll`/`read`). Если цикл — поллинг с периодическим sleep, будить
нечего: достаточно атомарного флага (`AtomicI32` + `store` в хендлере,
опрос на каждой итерации), и это проще — нет fd, нет `O_NONBLOCK`, нет
EINTR-ретраев, нет `FD_CLOEXEC` от утечки дескрипторов в детей. Цена — латентность
до одного тика. Так и сделано в Этапе 3 (`src/signal.rs`); если цикл станет
событийным (unix-socket с `poll`) — переходить на self-pipe/signalfd. В Этапе 5
условие **не сработало**: каналом для `status` выбран файл состояния, цикл
остался поллинговым, `signal.rs` не тронут.

Диспозиция `SIG_IGN` наследуется через `exec`, а установленный хендлер при `exec`
сбрасывается в `SIG_DFL`. Поэтому супервизору **нельзя** глушить SIGTERM через
`SigIgn`: дети унаследуют глухоту.

## Teardown дерева (ядро проекта, Этап 4 — реализовано)

Блокирующей `terminate_tree(pgid, grace)` **нет**: блокирующий grace
сериализуется по процессам (N × grace на shutdown из N процессов), не наблюдаем
извне и не проверяется `FakeClock`. Вместо неё — состояние на процесс,
продвигаемое обычным `tick()` по инъектируемым часам:

- `StopPhase::{Idle, Terminating { deadline }, Killing}` в `Supervised`;
- `begin_shutdown(sig)` — `killpg(pgid, sig)` каждой живой группе + дедлайн
  `now + stop_grace_secs` из конфига процесса;
- дедлайн наступил, лидер жив → `killpg(pgid, SIGKILL)`, фаза `Killing`;
- второй сигнал → `escalate_to_kill()`: SIGKILL всем группам сразу, без остатка
  grace;
- **выход лидера ⇒ немедленный SIGKILL-sweep остатка группы**, и в shutdown, и
  на пути рестарта. Grace защищает завершение *лидера*; после его смерти
  шефствовать над мягкой остановкой внуков некому.

Форвардинг Этапа 3 переведён с `kill(pid)` на `killpg(pgid)`: `forward_signal`
удалён, есть `process::signal_group(pgid, sig)`.

**Реапинг — гибрид, а не переход на ручной `waitpid`.** Владелец pid —
`std::process::Child`, реапит только он (`try_wait`), двойного реапинга нет по
построению. Обнаружение выхода — неразрушающий peek `waitid(P_PID, pid,
WEXITED | WNOHANG | WNOWAIT)` (`process::peek_exited`). Полный переход на
`waitpid` бесполезен: он реапит только **прямых** детей, а внуки при смерти
лидера уходят к `init`/subreaper и супервизору недоступны в принципе.

## Тестирование сигналов и деревьев (детерминированно)

Главная ловушка — протестировать только «простой child». Обязательно покрывать
случай «child, который сам форкнул детей».

Паттерн: **дочерние процессы-заглушки** (helper-скрипты или отдельные тестовые
бинарники), которые ведут себя предсказуемо, плюс файлы-маркеры и проверки
`kill(pid, 0)`:

- **Заглушка-падалка:** выходит с заданным кодом/по сигналу — для проверки
  restart policy (Этап 2). Код выхода/задержку задавать через argv или env.
- **Заглушка-ловец SIGTERM:** ставит хендлер, пишет маркер-файл «got SIGTERM»
  перед выходом — проверка форвардинга (Этап 3).
- **Заглушка-родитель с детьми:** форкает 2–3 долгоживущих ребёнка в своей
  группе, печатает их PID-ы в stdout/файл — проверка teardown дерева (Этап 4).
  Тест читает PID-ы и **поллит с дедлайном**, пока все не дадут
  `kill(pid, 0)` → `Err(ESRCH)`. Два уточнения, оба выстраданные:
  - **Считать зомби бесполезно** — зомби внуков принадлежат init, супервизору
    они не видны и не доступны для реапинга (см. граблю про `killpg(pgid, 0)`
    ниже). Наблюдаемое — исчезновение pid-а, а не отсутствие зомби.
  - **Внукам обязательно глушить SIGTERM** (`trap '' TERM`), иначе они умрут от
    того же группового SIGTERM, что и лидер, и тест останется зелёным даже при
    полностью удалённом SIGKILL-sweep — то есть будет проверять форвардинг
    вместо teardown. И тогда же нужен handshake **от самого внука** после
    `trap`: `echo $!` пишет родитель, он ничего не знает про то, дошёл ли
    субшелл до `trap`.
- **Заглушка-игнорщик SIGTERM:** глушит SIGTERM — проверка пути SIGKILL по
  таймауту (Этап 4).

Технические приёмы для детерминизма:
- Проверка «жив ли pid»: `nix::sys::signal::kill(pid, None)` (сигнал 0) →
  `Ok` = жив, `Err(Errno::ESRCH)` = мёртв.
- `tempfile` (dev-dep) — для скретч-директорий и маркер-файлов, чтобы не сорить
  в репо.
- Backoff/таймауты тестировать с инъекцией «часов» (трейт-абстракция над
  временем), чтобы не спать реальные секунды и не делать тесты флаки.
- Хелперы-заглушки задавать **инлайн-скриптами** для `/usr/bin/env sh -c` прямо
  в тест-файле. Не выносить в отдельные бинарники (`[[bin]]`/`tests/bin/`) и не
  писать исполняемый файл на диск — см. граблю ETXTBSY ниже.

### Грабли, на которые уже наступали

- **ETXTBSY.** Не создавать исполняемый файл на диске и сразу его `exec`-ать: в
  многопоточном тест-раннере это гонка с `fork()` (потомок наследует открытый
  на запись дескриптор), флейк примерно 1 прогон из 10. Запускать заглушки через
  `/usr/bin/env sh -c '<скрипт>'` или symlink на системный бинарник — так и
  сделано в `tests/signals.rs` и `tests/shutdown.rs`.
- **Готовность заглушки проверять по содержимому файла, а не по его наличию.**
  `echo $$ >> file` — это `open(O_CREAT)`, а потом отдельный `write()`; между
  ними файл существует и пуст. Поллинг на `path.exists()` попадает в это окно
  (тем шире, чем больше загружен раннер) и читает пустую строку. Ждать разбора
  содержимого.
- **Рукопожатие строить так, чтобы его успех означал нужный инвариант.** В
  `tests/signals.rs` трапы в `sh` взводятся ДО записи pid-файла, поэтому
  появление pid-файла = «ловушка взведена». Переставить строки местами — тест
  станет флейким молча.
- **`sh` выполняет trap только между командами.** Долгоживущая заглушка на шелле
  должна крутить цикл коротких `sleep 0.1`, а не один `sleep 100`, иначе реакция
  на сигнал задержится на всю длину сна.
- **Не маскировать флейки ретраями** — устранять причину. Новые тесты на сигналы
  прогонять подряд 10 раз, прежде чем считать зелёными.
- **`WNOWAIT` есть только у `waitid(2)`.** `waitpid(2)`/`wait4(2)` отвечают на
  него `EINVAL` (проверено на Linux 6.8). Неразрушающий peek делается только
  через `nix::sys::wait::{waitid, Id}`.
- **Зомби-лидер пиннит pgid — отсюда порядок peek → sweep → reap.** Пока лидер
  не реапнут, он существует как зомби, а pgid существующей группы ядро
  переиспользовать не может, поэтому `killpg` в этом окне гарантированно бьёт по
  своей группе. Реапнуть до `killpg` — открыть TOCTOU-окно и убить невиновных.
- **`killpg(pgid, 0)` бесполезен как проверка живости группы.** Зомби — всё ещё
  существующий процесс, поэтому группа с одним зомби-лидером отвечает успехом, а
  не `ESRCH`; и после реапинга лидера — тоже успехом, потому что убитые внуки
  висят зомби, пока их не реапнет init. «Группа мертва» не наблюдаемо через
  `killpg` ни в один момент — примитив «живость группы» в продакшен-код не
  вводить, ждать только лидера.
- **Смерть ВНУКА наблюдается только поллингом с дедлайном.** Прямого ребёнка
  реапит сам супервизор, поэтому `ESRCH` по нему детерминирован сразу. Внука
  реапит init, асинхронно, — до этого он зомби, и `kill(pid, 0)` по нему
  возвращает успех. Одиночный `assert` на `ESRCH` — гарантированный флейк.
- **Фоновый `cmd &` в `sh` глух к SIGINT, но не к SIGTERM.** POSIX предписывает
  шеллу выставлять асинхронно запущенной команде `SIGINT`/`SIGQUIT` в `SIG_IGN`.
  Поэтому дерево-тест на SIGINT ведёт себя иначе, чем на SIGTERM, — не списывать
  асимметрию на баг супервизора.
- **Сигналы коалесцируют в `PENDING`.** `AtomicI32` хранит только последний
  сигнал, поэтому два сигнала, доставленные до первого `take_pending()`,
  сливаются в один. Тест на «второй сигнал» обязан дождаться, что первый
  обработан, — например поллингом лога супервизора на строку `shutdown
  requested`, а не `sleep`-ом.
- **`tracing_subscriber::fmt` пишет в stdout**, не в stderr. Тест, который
  поллит лог супервизора, должен перенаправлять stdout (или оба потока).
- **Ограничение по времени у заглушки держать много больше таймаутов теста.**
  Заглушка, пережившая свой тест, — страховка от вечного процесса; заглушка,
  умершая раньше времени, выглядит как баг продукта (пропавший маркер или лишний
  рестарт).
- **`toml::to_string` падает на `None` без `skip_serializing_if`.** В TOML нет
  null, поэтому `Option`-поле обязано нести
  `#[serde(skip_serializing_if = "Option::is_none", default)]` — иначе первая же
  сериализация структуры, где поле пустое, вернёт ошибку, а не пропустит ключ.
  Проверять сериализацию именно в состоянии с `None`, а не только в «полном».
  И ещё: в TOML все скаляры таблицы обязаны идти **до** её подтаблиц, поэтому
  поле-`Vec<Struct>` (то есть `[[array-of-tables]]`) должно быть последним в
  объявлении структуры.
- **Атомарность файла состояния — tmp-in-same-dir + `rename`.** `tempfile` —
  dev-зависимость и в продакшен-код не тянется, поэтому имя временного файла
  фиксированное (`<path>.tmp`), а не рандомное: писатель ровно один. Директория
  обязана быть та же — `rename` атомарен только внутри одной файловой системы.
  `fsync` не нужен: защищаемся от читателя-наблюдателя, а не от падения ядра.
  Выигрыш — у читателя не бывает «полфайла», поэтому парс-ошибка у него
  означает реальную порчу, а не гонку.
- **Handshake e2e-тестов — по файлу состояния, а не по новой копии
  `wait_for_pid`.** Появление снапшота с процессом в `running` означает
  «демон поднялся И опубликовал», то есть ровно предусловие `status`; это ещё и
  не плодит четвёртую копию pid-хелпера (см. техдолг Этапа 4).
- **Каждый e2e-запуск бинарника обязан изолировать `--state-file` в свой
  tempdir.** Дефолтный путь один на uid: без флага параллельные тесты пишут в
  общий файл, а удаление файла при штатном выходе одного демона подставляет
  ножку другому. Это касается и старых тестов (`signals.rs`, `tree.rs`), а не
  только новых.

## Пирамида тестов

- **Юнит:** парсинг конфига (валидный/битый), логика policy (решение
  рестартить/нет по коду выхода), расчёт backoff — без реальных процессов.
- **Интеграционные:** реальный spawn заглушек, сигналы, teardown дерева — на
  реальном стеке процессов (детерминированные фейки, а не мок-HTTP).
